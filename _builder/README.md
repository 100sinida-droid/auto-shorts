# 봉안당 길잡이

전국 봉안시설 공공데이터로 봉안당 검색 사이트를 자동으로 만드는 저장소입니다.

## 폴더 구조 (2026-10 정리)

```
(저장소 맨 위)
├─ index.html  404.html  robots.txt  sitemap.xml  ads.txt  _worker.js
├─ place/    봉안당 694곳 개별 페이지 (시도별 폴더, 경기도는 북부·남부로 나눔)
├─ area/     시군구별 봉안당 페이지 196개 (시도별 폴더)
├─ bongan/   봉안당: 지역별 목록, 공설·사설, 가격 비교, 추천, 순위, 가까운 봉안당, 총비용 계산기, 명절 안내
├─ funeral/  장례식장·화장장
├─ guides/   장례·봉안 가이드
├─ tools/    장례 도우미: 지방·축문·49재·부고·장례 후 할 일
├─ info/     사이트 소개·문의·개인정보·약관·검색
├─ assets/   디자인(css)·기능(js)·검색 데이터·RSS·공유 이미지
├─ _builder/ 사이트를 만드는 프로그램과 자료 (이 설명서도 여기)
└─ .github/  자동 생성 설정
```

맨 위 파일과 각 폴더는 모두 100개 이하라 GitHub 웹 업로드로 나눠 올릴 수 있습니다.
1. 맨 위 파일 6개 + `bongan` + `funeral`
2. `guides` + `tools` + `info` + `assets`
3. `_builder` + `.github`

예전 주소(region/, type/, feature/, compare/, pages/, static/, data/)로 들어오면 `_worker.js` 가 새 주소로 자동으로 넘겨 줍니다.
GitHub 저장소에 남아 있는 예전 폴더(region, type, feature, compare, pages, static, data)와 맨 위의 og.png, rss.xml, README.md 는 지워도 됩니다.

## 올리는 방법 (페이지가 900개를 넘으므로 자동 생성 권장)

`_builder/config.json` 의 `mode` 가 `pages` 이면 시설 694곳과 시군구 196곳의 페이지를 따로 만듭니다. 파일이 1,000개 가까이 되므로 GitHub Actions 자동 생성을 쓰는 것이 편합니다.
1. 저장소 **Settings → Actions → General** 에서 Actions 사용을 허용하고, **Workflow permissions** 를 **Read and write permissions** 로 바꿉니다.
2. 이제부터는 `_builder` 폴더만 고쳐서 올리면 GitHub가 사이트 전체를 새로 만들어 저장소에 올리고, Cloudflare가 자동으로 배포합니다.
3. 바로 다시 만들고 싶으면 **Actions → 봉안시설 사이트 자동 생성 → Run workflow** 를 누릅니다.

손으로 올릴 때는 폴더마다 100개 이하라 폴더별로 나눠 올릴 수 있습니다.

## 참배 시간 넣기

`_builder/hours/visit_hours.csv` 에 시설명(공공데이터 이름과 똑같이), 평일, 주말·공휴일, 명절, 비고, 확인일을 한 줄씩 적으면 그 시설 페이지에 참배 시간이 표로 나옵니다. 적지 않은 시설은 "전화로 확인" 안내와 전화 단추가 나옵니다. '예시'로 시작하는 이름은 무시됩니다.

## 페이지 구성 방식

`_builder/config.json` 의 `mode` 로 고릅니다.
- `pages` (지금 설정): 시설마다, 시군구마다 페이지를 따로 만듭니다. 검색 노출에 가장 좋습니다.
- `compact`: 시설 상세 정보를 시도 페이지 안에 모아 둡니다. 파일 약 100개.
- `full`: 시설마다 페이지를 따로 만듭니다. 파일 약 1,000개라 웹 업로드 대신 GitHub Desktop이나 자동 생성(Actions)이 필요합니다.

## 가격 정보

`_builder/prices/` 폴더의 CSV를 읽어 시설별 가격표, 가격 비교 페이지, 예산 추천에 씁니다.

- `kfcpi_bongan_prices_20230601.csv` : 한국장례문화진흥원 장사시설 가격정보(2023-06-01) 중 봉안시설 부분
- `kfcpi_bongan_facilities_20230601.csv` : 같은 자료의 봉안시설 목록. 가격표 시설을 전화번호·주소로 찾아 연결하는 데 씁니다
- `prices_manual.csv` : 직접 조사했거나 제휴처에서 받은 가격을 적는 곳. 한 줄에 한 항목
  예) `하늘의문,인천광역시,개인단,1위 15년,3500000,15년,눈높이 칸,2026-10-12`

새 가격 파일(CSV)을 이 폴더에 넣고 `build.bat` 를 실행하면 자동으로 반영됩니다.

## 제휴 시설 · 상담 신청 · 사은품 (partner/)

- **제휴 시설 목록**: `partners/partners.csv` (엑셀로 열어 고치고 CSV로 저장). 한 줄이 한 시설입니다.
  - `코드`는 주소에 쓰이는 영문 이름(바꾸지 마세요), `노출`을 N으로 하면 사이트에서 숨깁니다.
  - `공공데이터시설명`에 봉안시설 현황의 시설명을 적으면 주소·전화·편의시설·가격이 자동으로 붙고, 그 시설 페이지에 「제휴」 표시와 상담 안내가 나옵니다. 여러 개면 `;`로 구분.
  - 공공데이터에 없는 시설(수목장 등 9곳)은 `주소`·`전화`를 직접 채워 주세요. 주소가 있어야 지도 길찾기·가까운 화장장이 나옵니다.
  - `분양가`(예: `개인단 350만 원부터;부부단 700만 원부터`), `관리비`, `대중교통`, `자가용`, `특징`(`;`로 구분), `한줄소개`를 채우면 시설 페이지에 그대로 나옵니다.
- **사진**: `partners/images/코드-1.jpg`, `코드-2.jpg` … 시설마다 4장까지. 1번이 대표 사진입니다. 사진은 시설에서 받은 것만 쓰세요(저작권).
- **사은품·회원코드**: `config.json` → `partner` 한 곳만 고치면 제휴 페이지, 첫 화면, 신청 완료 화면, 통계의 사은품 자동 계산까지 함께 바뀝니다.
  - `gifts`: 계약 금액 구간(`min` 이상 `max` 미만, 원 단위, `max`가 null이면 '이상')과 사은품 이름·금액.
  - `gift_terms`: 지급 조건 문구. `{code}`는 회원코드로 바뀝니다.
  - `kakao_channel_url`, `consult_phone`: 채우면 모바일 하단에 카카오톡·전화 상담 단추가 생깁니다.
- **상담 신청 받기**: 신청서는 `/api/lead`로 저장되고 `/stats/leads`(통계 비밀번호)에서 상태·방문 예약·계약 금액·사은품을 관리합니다. 엑셀(CSV)로도 받을 수 있습니다.
- **알림 (Cloudflare Pages → 설정 → 변수 및 비밀, 저장 후 다시 배포)**
  - 카카오톡: `KAKAO_REST_KEY` (+필요하면 `KAKAO_CLIENT_SECRET`) → `/stats/leads`의 「카카오톡 연결하기」. 자세한 순서는 그 페이지의 '설정 방법 보기'.
  - 이메일: `RESEND_API_KEY` (resend.com에 shinnamho@naver.com으로 가입해 만든 키). 받는 주소를 바꾸려면 `LEAD_EMAIL`.
- 개인정보: 신청서에 수집·이용, 제3자 제공 동의가 있고, 개인정보처리방침에도 반영했습니다. 업체에 고객 정보를 넘길 때는 동의 범위(성함·연락처·고인 성함·희망 방문일)만 넘기세요. 종료·사은품 지급 후 1년이 지난 신청은 자동으로 지워집니다.

## 방문 통계 (/stats)

맨 위의 `_worker.js` 가 방문 기록을 저장하고 통계 페이지를 보여 줍니다. Cloudflare Pages에서만 작동합니다.

처음 한 번만 Cloudflare 대시보드에서 설정합니다.
1. **Workers 및 Pages → D1 SQL 데이터베이스 → 만들기** (이름 예: `bongan-stats`)
2. Pages 프로젝트 → **설정 → 바인딩 → 추가 → D1 데이터베이스**: 변수 이름 `DB`, 방금 만든 데이터베이스 선택
3. Pages 프로젝트 → **설정 → 변수 및 비밀 → 추가**: 이름 `STATS_PASSWORD`, 값은 원하는 비밀번호 (유형: 비밀)
4. **배포** 탭에서 최근 배포를 다시 배포하거나 파일을 한 번 더 올리기
5. `https://사이트주소/stats` 접속 → 비밀번호 입력

볼 수 있는 것: 오늘·기간 방문자 수, 날짜별 그래프, 유입 경로(검색 포털·직접 방문·블로그/SNS·다른 사이트·배너), 포털별 방문, 검색어, 배너별 방문, 많이 본 페이지, 사이트 안 검색어, 기기, 최근 방문 목록.
배너나 블로그 글에 걸 주소는 통계 페이지의 **추적 링크 만들기** 로 만들면 어느 배너로 들어왔는지 따로 집계됩니다.
`_worker.js` 는 `_builder` 와 `.github` 폴더를 바깥에서 열어 볼 수 없게 막는 일도 합니다.

## 설정 바꾸기

광고 자리와 가격은 `_builder/config.json` 의 `ads` 항목에서 고칩니다. 지금은 문의 페이지 가격표에만 쓰이고 사이트에는 배너가 나오지 않습니다. (`show_empty` 를 `true` 로 바꾸면 각 자리에 "광고 문의" 칸이 보입니다)

`_builder/config.json` 에서 `site_url`(사이트 주소, 넣어야 sitemap.xml 이 만들어짐), `contact_email`(문의 이메일), `adsense_client`(애드센스 승인 후 코드)를 고친 뒤 GitHub에서 그 파일만 다시 올리면 자동으로 사이트가 다시 만들어집니다.
